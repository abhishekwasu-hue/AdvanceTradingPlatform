## HC4-5: H-C4 round cap (13 Oct)

- **What kept failing.**
  - 12 rounds on a trilingual free-text checker. The causes were Marathi / Hindi / Hinglish grammar (futures, subjunctives, postpositions), comma-joined clauses, and the data-row, past-marker, count and linked-expiry exemptions.
  - Then 2 rounds on the English-only design: a strict word list, fact-bound numbers and a closed data vocabulary.
- **Why the design invited it.** Any checker of free AI text is an open-ended natural-language classifier. A block list misses synonyms, and an allow list misses compositions.
- **The reviewer's reasoning (rounds 13-14).**
  - Round 13 composed forecasts purely from allowed words. Examples: "Spot to rise to max pain 22800 on Thursday", "Spot ends at max pain 22800 on 2026-10-30", "PCR 1.3: a rise". Hidden Unicode marks, symbols and arrows, and all-caps headline words, also slipped through.
  - Those were fixed by removing words. Round 14 still found forecasts built only from allowed nouns and prepositions: spelled-out times ("in one week", "within two sessions"), a possessive or "for" expiry ("The close for this expiry is max pain 22800."), "from X to <level>", and "is the bottom / top for this expiry".
  - The reviewer's conclusion: a word allowlist cannot stop allowed nouns and prepositions from forming a forecast.
- **Decision (round cap): shrink, do not patch.**
  - Multiview shows only deterministic text: each view's `lines` and `rules_summary`. No model is called, and no free AI text is ever shown.
  - The checker is deleted, together with its tests: the vocabulary layer, the time-ahead / composition rules, the Unicode and non-Latin withholding, and the AI wording paths and prompts.
  - The response keeps its shape: `report_source` and `summary.source` are "rules", `llm_calls` is 0, and `usage` is empty.
- **Follow-up: AI ordering.** If the AI is brought back, it may only select and order sentence ids from the rules-generated set (for example `{"order": [...], "omit": [...]}`). The server validates every id against that set and ignores anything else (unknown ids, extra fields, text), falling back to the rules' order. Risk lines should never be omissible. This was not built here: the ordering adds little, and dropping the model removes the whole free-text attack surface.
- **Untrusted strings in the rules' lines.** The user's symbol never enters a line. The sentiment label appears only from its closed vocabulary. A global market is named only if it is one of the market memory's own markets (`global_cues.MARKETS`); any other stored symbol is left out of the "Global markets" line.

## AI-1: the #230 AI call filter review loop (note, 2026-10-13)

- **What kept failing.** Twelve review rounds traded one leak for another around a whitelist of "recap tails" (what may follow "close 4050" in a market recap) set against "advice tails" (what turns "close at 1500" into an order). Each widening of the whitelist opened calls ("... as a precaution", "... - the safest choice"); each narrowing blocked recaps ("... is key support", "... after results"). Marathi / Hindi / Hinglish patterns doubled the surface.
- **Why the design invited it.** The filter was an open-ended natural-language classifier: it tried to decide, from wording alone, whether free text is a call. Natural language has no closed set of tails, so every round could find another one.
- **The two-layer design from here.**
  - (a) A small, strict advice-pattern list that fails closed: `app/ai/call_detect.py` + `app/ai/output_filter.py`, English only. AI text that is not plain English is withheld (`call_detect.SCRIPT_LABEL`, reason `output_filter.NOT_ENGLISH_REASON`) instead of being read with per-language patterns. The Copilot strategy interview's Marathi lines are fixed, stored translations (`app/ai/interview.py`); they never pass through the filter (`tests/test_ai_call_filter.py`).
  - (b) Structural safety: AI text may only describe system-supplied data, never invent levels. The fact-bound number check is `app/ai/grounding.py` (`check_numbers`, `check_tickers`, `check_direction`). It runs before the output filter on every current AI text surface: copilot `grounded`, knowledge, agent `_verify`, generator, thesis `numbers_check`, scanner, support bot. It only stops invented numbers and tickers. It is **not** a backstop for a call on a level the facts supply: "INFY 1500 par exit karo" passes it when 1500 is in the facts.
  - Plain English is enforced structurally: AI text with any non-ASCII letter (non-Latin script, small caps, accented letters; a lone options greek such as Δ or θ excepted), a combining mark or a hidden / default-ignorable character is withheld (`call_detect.SCRIPT_LABEL`, `output_filter.NOT_ENGLISH_REASON`).
- **Greek exception follow-up (open).** A lone options greek (Δ, θ, σ, ...) not touching a letter is allowed; tighten it to a greek followed by a number ("Δ 0.45") if the model is seen using lone greeks as letters.
- **Accented-name follow-up (open).** Any accented letter withholds the text (it closes the "Bùy RELIANCE" bypass), so a reply naming "Société Générale" or "Nestlé" is withheld; an allow-list of instrument names from the master is the likely fix.
- **Lint follow-up (open).** A test or lint that fails when a module calls `output_filter.check` / `screen` / `findings` on AI text without a `grounding.check_numbers` call on the same text, so a new AI surface cannot skip layer (b).
- **Open for the owner.** Provisional decisions:
  - ~~Copilot, knowledge and thesis prompts still ask the model for Marathi when `lang == "mr"`.~~ Done (English-only cleanup, Oct 2026): every prompt outside the strategy interview says "English only", whatever the message's language.
  - ~~`output_filter` keeps its Marathi / Hindi guarantee and advice words and its Marathi framing line.~~ Done (English-only cleanup): the lists and the framing line are English only.
  - Hinglish written in Latin script ("TCS kharido", "1500 la close kara") is no longer detected, and layer (b) does not catch it when the level is in the facts (above). Accepted under the English-only directive; revisit if the model is seen writing Hinglish.

### MA-1: domain and DNS, then a trusted certificate

1. **Buy a domain** at any registrar. The app host is `atp.<domain>`, the name `docs/DEPLOY_HOSTINGER.md` already
   uses.
2. **Add the DNS record.** In the registrar's DNS page add an `A` record: name `atp`, value `<server-ip>` (the server's IP, from your own notes), TTL
   300. Add no `AAAA` record unless the server's IPv6 is set up and open on ports 80 / 443. A wrong `AAAA` record
   makes certificate issuance fail.
3. **Wait and check.** Wait 5-30 minutes, then check from any computer that `dig +short atp.<domain>` prints
   `<server-ip>`.
4. **Ports.** Ports 80 and 443 must stay open on the server. Let's Encrypt checks the domain through them.
5. **Switch the server.** Outside market hours, edit `/opt/atp/.env` with `nano`:
   - `DOMAIN=atp.<domain>`;
   - `ACME_EMAIL=<an address that gets certificate expiry notices>`;
   - `CADDYFILE=Caddyfile`;
   - if `PUBLIC_BASE_URL` is set, `PUBLIC_BASE_URL=https://atp.<domain>`.

   Then run `/opt/atp/deploy/atp.sh deploy`. `ALLOWED_ORIGINS` and `FRONTEND_URL` follow `DOMAIN` by themselves
   (`docker-compose.prod.yml`).
6. **Caddy gets the certificate.** It obtains a Let's Encrypt certificate for the domain on its own and renews it
   (`deploy/Caddyfile`, automatic HTTPS). Nothing is installed or rotated by hand.
7. **Verify:**
   - `curl -sI https://atp.<domain>/api/system/health` (no `-k`) answers 200;
   - the browser shows no certificate warning;
   - Chrome on Android offers "Install app";
   - Settings → Alert delivery → Push notifications can be enabled.
8. **Follow-ups:**
   - Update the Upstox app's redirect URL to `https://atp.<domain>/api/broker/upstox/oauth/callback`.

### MA-3: upload keystore (Android signing)

1. **Get `keytool`.** It ships with any JDK, including the one inside Android Studio.
2. **Create the keystore.** Replace the `<...>` parts. Type the password when `keytool` asks, not on the command line,
   so it stays out of the shell history.

   ```
   keytool -genkeypair -v \
     -keystore atp-upload.jks -storetype PKCS12 \
     -alias <KEY_ALIAS> \
     -keyalg RSA -keysize 4096 -validity 10000 \
     -dname "CN=<YOUR NAME>, O=<COMPANY OR YOUR NAME>, C=IN"
   ```

   A PKCS12 keystore uses one password for the store and the key, so `ANDROID_UPLOAD_KEY_PASSWORD` is the same value
   as `ANDROID_UPLOAD_KEYSTORE_PASSWORD`.
3. **Fingerprint (public, safe to share).** Run `keytool -list -v -keystore atp-upload.jks -alias <KEY_ALIAS>` and
   copy the `SHA256:` line into the B2 PR for `assetlinks.json`.
4. **Base64 the file:**
   - Linux: `base64 -w0 atp-upload.jks > atp-upload.jks.b64`
   - macOS: `base64 -i atp-upload.jks -o atp-upload.jks.b64`
   - Windows PowerShell:
     `[Convert]::ToBase64String([IO.File]::ReadAllBytes("atp-upload.jks")) | Set-Content -NoNewline atp-upload.jks.b64`
5. **Create the GitHub environment.** GitHub → repository → Settings → Environments → **New environment**
   `android-release`. Under "Required reviewers" add yourself, so no release build runs without your click.
6. **Add the four secrets to that environment:**
   - `ANDROID_UPLOAD_KEYSTORE_BASE64`: the content of `atp-upload.jks.b64`;
   - `ANDROID_UPLOAD_KEYSTORE_PASSWORD`;
   - `ANDROID_UPLOAD_KEY_ALIAS`;
   - `ANDROID_UPLOAD_KEY_PASSWORD`.

   With the CLI: `gh secret set ANDROID_UPLOAD_KEYSTORE_BASE64 --env android-release < atp-upload.jks.b64`, and for the
   others `gh secret set <NAME> --env android-release`, which prompts without echoing the value.
7. **Delete `atp-upload.jks.b64`.**
8. **Backups.** Keep the keystore and its password in two places that are not online together: a password manager
   entry (the file as an attachment, plus the password and alias) and an encrypted USB drive kept elsewhere.
   - Never put them in git, e-mail, chat or an unencrypted cloud folder.
   - Do not reuse the key for anything else.
   - **Why it matters:** before Play, a lost key means the installed app cannot be updated. You must uninstall it and
     reinstall a build signed with a new key, which loses the app's local data. After Play App Signing (MA-4), Google
     can reset a lost upload key through Play support.
