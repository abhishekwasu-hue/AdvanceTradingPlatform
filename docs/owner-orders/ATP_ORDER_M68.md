# ATP ORDER M68 - Universal trade settings (owner order, 31 Oct, verbatim)

M68 · ATP · UNIVERSAL TRADE SETTINGS — remove every hard-coded / pre-chosen trading default (business product rule, permanent)
Why: ATP is a business product for every kind of trader. It must never impose one trader's logic, method or risk management on others. ATP provides the full professional toolset; each user decides everything in his own Trade settings after login. Too many built-in limits = users leave.
Rule (binding for all present and future code): ATP never pre-chooses, caps or silently changes a trading choice. What remains fixed is only what the exchange or the broker enforces (lot-size multiple, freeze quantity → auto-split, market hours/holidays, broker margin and order-type support, broker rejections) and the kill switch the user himself presses. Exits are never blocked. AI never places or changes orders.
TS-1 Audit first (post the table, then fix without waiting): every hard-coded or default trading value anywhere in backend + frontend — sizing (lots, quantity, risk %, ₹ risk), SL / target / trailing / break-even / time exit, square-off and cut-off times, product (MIS/NRML), order type (market/limit/SL/SL-M), limit-price protection %, slippage, strikes (ATM/OTM n), spread width, expiry choice, hedge, re-entry, max trades/positions/lots, daily loss, cool-down, min R:R, margin safety, VIX gate, approval mode, trading windows, paper brokerage/charges model, seller-pack or template presets, anything chosen "for" the user. Columns: file:line, current value, who it affects, new home (user setting / exchange-broker fact / delete).
TS-2 Move every user choice into ONE "Trade settings" area (Settings › Trade settings) with sections: Order defaults (product, order type, price protection), Position size, Exits (SL, target, trailing, time exit, square-off), Options (strike rule, width, expiry, hedge), Risk limits (each check with its own on/off switch), Automation (approval mode, trading window, re-entry), Paper account (capital, charges model). Every field starts EMPTY / OFF ("Not set") — no value is pre-filled by ATP. The user can override any of them per strategy / per bot / per order in the ticket.
TS-3 First use: if a required field for an action is not set (e.g. quantity for an order, product for an F&O order), ask the user in the ticket itself with the field focused — never fill it silently, never refuse with an internal message. A "Save as my default" tick next to each field.
TS-4 Templates, strategy library, seller packs, Copilot drafts, the price-action engine (M66): they may SUGGEST values, shown as suggestions the user accepts or edits; nothing is applied until the user saves it. The owner's own settings live only in the owner's account.
TS-5 Pro-trader facilities available to every user (settings, not defaults): all order types incl. SL/SL-M/GTT where the broker supports them, bracket-style SL+target, trailing by points/%/ATR, combined/strategy exits (overall SL/target/trailing/OCO), partial exits, scale in/out, per-leg and per-structure exits, multi-broker routing (M45), hotkeys/quick ticket, basket orders, position sizing modes (fixed lots, fixed quantity, % capital, risk-based), time-based exits, re-entry rules, trading-window per bot.
TS-6 Migration: existing users keep exactly what they themselves saved; every value they never saved becomes "Not set"; a one-time notice "ATP no longer pre-sets trading values — review your Trade settings".
TS-7 Guard test in CI: a scanner that fails the build when a new trading literal appears in execution / risk / strategy / ticket code outside the settings registry (allow-list for exchange/broker facts with a reason). Unit tests for every moved value; e2e: a new user places a PAPER order only after choosing quantity and product in the ticket.
TS-8 Proof: the TS-1 table before/after, screenshots of Trade settings (phone + desktop) and of the ticket asking for a missing field. One PR per section; merge on green CI.
