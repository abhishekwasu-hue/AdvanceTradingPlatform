# Strategy DSL reference

`dsl_version: 1` · Source of truth: `backend/app/strategy_engine/declarative.py`
(`CustomStrategyConfig`). Every custom strategy, whether built in the visual Strategy Builder,
posted to `POST /api/custom-strategies`, generated by the AI copilot or copied from the
marketplace, is one JSON document in this shape. The same document drives `/signal`, backtests,
paper trading and LIVE (ADR 0005), so a backtest is a faithful rehearsal.

## Versioning

- Documents are stored immutably as strategy versions (`GET /api/custom-strategies/{id}/versions`);
  editing appends a version and moves the live pointer, rollback repoints it.
- `dsl_version` is implicit today (1). Additive fields with defaults keep every stored document
  valid; a breaking change bumps the version and ships a migration that rewrites stored
  `config_json`. This file is updated in the same commit as any schema change.

## Document

```json
{
  "name": "EMA pullback long",
  "timeframe": "5min",
  "long_conditions":  [ <Condition>, ... ],
  "short_conditions": [ <Condition>, ... ],
  "stop_loss_atr_mult": 1.0,
  "atr_period": 14,
  "target_rr": [1.5, 2.0],
  "min_rr": 1.2
}
```

| Field | Type | Default | Meaning |
|-------|------|---------|---------|
| `name` | string | required | Shown in the UI and in signal reasons. |
| `timeframe` | string | `"5min"` | Candle timeframe the conditions are evaluated on (`1min`, `3min`, `5min`, `15min`, `30min`, `60min`, `1D` as supported by the market-data service). One timeframe per strategy. |
| `long_conditions` | Condition[] | `[]` | ALL must hold on the latest bar for a LONG signal. |
| `short_conditions` | Condition[] | `[]` | ALL must hold on the latest bar for a SHORT signal. At least one of the two lists must be non-empty. |
| `stop_loss_atr_mult` | number > 0 | `1.0` | Stop = close ∓ ATR(`atr_period`) × this. |
| `atr_period` | int 1..500 | `14` | ATR lookback for the stop. |
| `target_rr` | [number, number] | `[1.5, 2.0]` | Two targets as R-multiples of the stop distance. |
| `min_rr` | number > 0 | `1.2` | Signals whose first target/risk ratio is below this are downgraded to NO_TRADE by the base engine. |

### Condition

```json
{ "left": <Operand>, "operator": "CROSSES_ABOVE", "right": <Operand> }
```

| Operator | Holds when |
|----------|-----------|
| `GT`, `GTE`, `LT`, `LTE` | `left` vs `right` on the latest bar. |
| `CROSSES_ABOVE` | previous bar `left <= right` and latest bar `left > right`. |
| `CROSSES_BELOW` | previous bar `left >= right` and latest bar `left < right`. |

A condition with insufficient history (indicator still NaN, or fewer than two bars for a cross)
does **not** hold and the whole side fails closed.

### Operand

```json
{ "type": "indicator", "indicator": "EMA", "period": 20 }
{ "type": "value", "value": 30 }
```

| `type` | Fields | Notes |
|--------|--------|-------|
| `value` | `value` (number) | A constant, e.g. RSI threshold. |
| `indicator` | `indicator`, `period` (1..500, default 14), `multiplier` (> 0, SUPERTREND only, default 3.0) | Computed on the strategy timeframe. |

Indicators: `CLOSE`, `OPEN`, `HIGH`, `LOW` (price columns, no period), `EMA`, `SMA` (on close),
`RSI`, `ATR`, `ADX`, `PLUS_DI`, `MINUS_DI`, `SUPERTREND`. Indicator implementations live in
`backend/app/indicators/` and are shared with every inbuilt strategy.

## Evaluation semantics

1. Warm-up: the strategy needs `max(period over all operands) + 5` bars and at least
   `atr_period + 5`; before that it returns NO_TRADE("Insufficient history").
2. Long side is evaluated first; if all long conditions hold the signal is LONG with
   `stop = close - ATR × mult`, targets from `target_rr`, score 70, and one reason per condition
   (its human label, e.g. `EMA(9) crosses above EMA(21)`).
3. Otherwise the short side is evaluated the same way with the mirrored stop.
4. Otherwise NO_TRADE("No custom rule set fully matched on the latest bar").
5. Position sizing, risk limits (ADR 0003), entry refusals (ADR 0004), exit rules (trailing,
   break-even, time exits) and regime filters are applied *outside* the DSL by the deployment,
   identically in backtest and live.

## Examples

**RSI mean reversion (long only)**
```json
{"name":"RSI dip","timeframe":"5min",
 "long_conditions":[{"left":{"type":"indicator","indicator":"RSI","period":14},"operator":"LT","right":{"type":"value","value":30}},
                    {"left":{"type":"indicator","indicator":"CLOSE"},"operator":"GT","right":{"type":"indicator","indicator":"EMA","period":200}}],
 "stop_loss_atr_mult":1.5,"target_rr":[1.5,2.5]}
```

**Supertrend flip with ADX filter (both sides)**
```json
{"name":"ST flip","timeframe":"15min",
 "long_conditions":[{"left":{"type":"indicator","indicator":"CLOSE"},"operator":"CROSSES_ABOVE","right":{"type":"indicator","indicator":"SUPERTREND","period":10,"multiplier":3}},
                    {"left":{"type":"indicator","indicator":"ADX","period":14},"operator":"GT","right":{"type":"value","value":20}}],
 "short_conditions":[{"left":{"type":"indicator","indicator":"CLOSE"},"operator":"CROSSES_BELOW","right":{"type":"indicator","indicator":"SUPERTREND","period":10,"multiplier":3}},
                     {"left":{"type":"indicator","indicator":"ADX","period":14},"operator":"GT","right":{"type":"value","value":20}}]}
```

## Validation errors you will see

- `A custom strategy needs at least one long or short condition` - both lists empty.
- `period` outside 1..500, `multiplier` or `stop_loss_atr_mult` not > 0 - 422 from the API.
- Unknown `indicator`/`operator` - 422 (the Literal types reject them).
