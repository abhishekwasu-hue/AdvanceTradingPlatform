# Owner order M45 — Multi-broker accounts (Primary / Secondary) with settings-driven routing (25 Oct, verbatim)

M45 · Multi-broker accounts (Primary / Secondary) with settings-driven routing

MB-0 Scope and safety. Multi-account applies only to broker accounts owned by the SAME logged-in user. No copying into other ATP users' accounts, no subscriber/strategy-provider mode. Research (R25): copiers use leader/follower with per-follower sizing; Indian broker APIs and the SEBI retail algo framework are per account (static IP, 2FA, OPS limit), so each connected account needs its own compliant link. Add a one-line note in Settings and docs that a lawyer must clear this before LIVE.
MB-1 Accounts registry. Settings > Broker accounts: add/remove several broker connections (own API credentials per account, stored encrypted, never in repo/logs/screenshots). Per account: label, broker, status (connected / token expired / error), Enabled toggle, role Primary or Secondary (exactly one Primary; changing it asks confirmation), optional user-named group for Secondaries. Show token-expiry and daily re-login state per account.
MB-2 Sizing per account. Mode: Fixed lots / Multiplier x Primary lots / % of account capital; default Multiplier 1. Round down to lot multiple; if < 1 lot, skip that account with a visible reason. Respect freeze-limit splitting per account. All numbers are settings, not code constants.
MB-3 Routing matrix (Settings > Execution routing). Rows = order class: Entry, Adjustment/roll, Exit (manual), Combined/strategy exit (CX/SX), Stop-loss/target. Columns = Primary + each Secondary group (checkboxes). Defaults: Entry -> Primary only; others follow positions (MB-4). Per-order override in the ticket: "Run on: Primary / Primary + group X / All", with the resolved account list shown before confirm.
MB-4 Exits follow positions. Any exit, SL, target, trailing or combined exit runs on EVERY account that actually holds that position, whatever the routing matrix says; routing governs new entries/adjustments only. Exits are never blocked by another account's failure, margin or disconnect. Shorts-first ordering inside each account. Combined exits keep one overall rule and also show per-account legs.
MB-5 Independent execution and failures. Each account gets its own order with its own client-order-id and result row (placed / filled / rejected / pending). No automatic rollback of accounts that succeeded. Setting "Secondaries only after Primary accepted" (default ON for entries, OFF for exits). A failed/disconnected account => critical alert (in-app + Telegram if configured) with reason and one-tap retry or manual action; position mismatch between accounts is flagged on the dashboard. Immediate reconcile via broker client-order-id (as TM-2) per account.
MB-6 Pre-send checks per account: margin, lot/freeze limits, valid token, segment allowed. A failing account is skipped with an alert; others continue. Never silent.
MB-7 Views. Positions, Orders, P&L: tabs "All accounts" (aggregated, with account badge) and per account. Primary/Secondary badge wherever an account is named. Paper mode behaves identically (simulated accounts); no paper-vs-live feature split.
MB-8 Audit and safety. Log every routing decision (what, which accounts, why) and result; no secrets in logs. AI never places, blocks or changes orders. LIVE stays OFF until the owner switches it. Org name from config ("My Organisation").
MB-9 Deliver: short design note in docs (no server addresses/credentials); tests for routing matrix, exits-follow-positions with one account failing, partial failure, rounding/skip, token expiry; screenshots of the Broker accounts page, routing matrix and ticket resolved-account list; report which broker adapters already support multiple connections and which need work.
