0. Source and target
 Source (Trade repo, file oi_analysis.py, ~840 lines, plus the banner block in page_dashboard.py and the 5-minute oi_snapshot_collector.py). Public functions to port, with their rules:
 - classify_oi_price_action(oi_now, oi_prev, premium_now, premium_prev, oi_threshold_pct=2.0, premium_threshold_pct=1.0): OI↑+premium↓ = Writing; OI↑+premium↑ = Buying; OI↓+premium↑ = Short Covering; OI↓+premium↓ = Long Unwinding; below thresholds = Flat/Unclear; missing previous = Insufficient data.
 - generate_oi_price_signal(put_class, call_class): Put Writing / Call Short Covering / Put Unwinding / Call Buying are bullish; Call Writing / Put Short Covering / Call Unwinding / Put Buying are bearish; both sides → MIXED; nothing → NEUTRAL. Messages (English, underlying-generic): "Put writing rising + Call short covering → avoid shorting calls; {underlying} bias bullish", "Call writing rising → avoid shorting puts; {underlying} bias bearish", "Mixed signals — no clear direction, stay cautious", "No clear activity".
 - compute_oi_signal_with_hysteresis(diff, put_oi, call_oi, recent_snapshots, lookback_for_strength=3, confirm_count=3): diff = total put OI − total call OI over ATM±N strikes; Strong/Weakening from growth vs the snapshot 3 back; direction flips only after confirm_count consecutive snapshots with the new sign AND a genuine rotation (is_genuine_rotation: call and put OI moving in opposite directions, each ≥ min_change_pct) confirmed for 2 consecutive comparisons; while unconfirmed, show the old direction as "Weakening", never as "Strong".
 - reconcile_with_diff_level(direction, message, diff, call_oi, put_oi, stable_signal, significance_pct=10): if momentum (banner) contradicts the hysteresis-confirmed stable signal → MIXED; if it contradicts the overall level (|diff| / total OI ≥ significance_pct) → MIXED with the diff side and size in the message.
 - compute_pcr_signal / compute_pcr_zone_label: five bands — PCR < 0.70 Oversold (contrarian; bear-trap risk), 0.70–0.90 mildly bearish (not yet oversold), 0.90–1.0 Sideways (range-bound), 1.0–1.3 mildly bullish (not yet overbought), > 1.3 Overbought (contrarian; bull-trap risk). Band edges are configuration, not constants.
 - compute_oi_price_matrix(total_oi, prev_total_oi, price, prev_price): long buildup / short buildup / short covering / long unwinding with strength Strong vs Weak/Temporary.
 - compute_max_pain(chain) (ATP already has option_chain/analysis.compute_max_pain — reuse, do not duplicate).
 - compute_rollover_proxy(near_chain, next_chain, atm_strike): OI share already in the next expiry + cost of carry from put-call-parity synthetic futures (near vs next); bias from the sign.
 - swing_oi_gate(direction, oi_price_matrix, pcr_bias, max_pain, price, rollover, max_opposing=1): count opposing vs supporting signals; block only when opposing > max_opposing (conflict filter, not strict confirmation).
 - check_oi_diff_entry_gate(direction, signal): own-direction Strong or opposite-direction Weakening passes; own-direction Weakening, NEUTRAL or missing data fails (fail-closed). check_oi_confirmation strictness A (conflict filter) / B (strict).
 - check_oi_wall_confirmation(chain, level, direction, step): nearest strike to a level; bearish needs positive CE OI change since the day's baseline, bullish needs positive PE OI change.
 - find_psychological_level(price, direction, round_to): next round number in the trade direction (round_to is per-underlying configuration).
 - check_pcr_gate (PCR limits per direction; stale snapshot ⇒ fail-closed with max_age_minutes), check_iv_change_gate (today's ATM IV vs the average of recent sideways-classified days; above the limit ⇒ no new entries; stale/insufficient ⇒ fail-closed).
 - compute_dte, fetch_and_save_oi_snapshot (5-minute slots, ATM±N by per-underlying strike step, totals of OI and premium, per-strike OI history, idempotent per slot), aggregate_oi_history (5/10/15-minute views; OI is a level, so take the last value per bucket).
 Target (ATP): backend/app/option_chain/ (analysis.py exists with moneyness/activity/max pain/bias — extend, keep its models), a new option_chain/oi_regime.py for the ported logic, option_chain/snapshots.py for the collector, alerts via the existing alerts/dispatcher (Telegram, email, webhook, web push, SMS already implemented) and notifications/service.

1. Design
 - Pure functions first (oi_regime.py): no DB, no broker calls inside the math; inputs are typed dataclasses/pydantic (ChainSnapshot, SnapshotHistory); every threshold is a parameter with defaults loaded from tenant/underlying settings (strike step, ATM range, thresholds, PCR bands, hysteresis counts, stale age). Settings editable on the dashboard, never hardcoded.
 - Snapshot collector: worker job every 5 minutes during the venue session (session calendar; crypto later), per enabled underlying (index and stock options), fetches the chain through the tenant's broker/vendor seam, stores oi_snapshots (totals, diff, delta, signal, premiums, underlying price, ATM) and strike_oi_snapshots (per strike CE/PE OI) in Postgres via the data lake conventions; idempotent per 5-minute slot; day baseline OI table for wall checks; stale detection.
 - Banner state machine: compute per underlying per snapshot: direction (BULLISH/BEARISH/MIXED/NEUTRAL), message, put/call classes, stable signal (hysteresis), PCR value and band label, DTE, max pain, OI-price matrix, rollover proxy. Persist banner_states with history so changes are detectable and auditable.
 - API: GET /api/option-chain/{underlying}/banner (current), /history?date=&interval=5|10|15, /strikes (per-strike OI history), /settings (GET/PUT, per tenant/underlying). Numbers carry data timestamps.
 - Frontend: Banner component (English) — colored left border by direction (bullish/bearish/mixed/neutral theme tokens), headline message, second line "Put: {class} · Call: {class}", third line "PCR {value} — {band label}", DTE chip, max pain chip, stale/market-closed chip; placed on the dashboard, the option-chain page and the chart's options layer (CHARTING_SPEC); history table with 5/10/15 views; per-strike OI chart. First snapshot of the day shows "Insufficient data — history builds through the session".
 - Gates exposed to the strategy engine as reusable checks (oi_diff_entry_gate, pcr_gate, iv_change_gate, swing_oi_gate, oi_wall_confirmation) with fail-closed behaviour when data is stale; strategies opt in via settings (Strategy Builder conditions). Exits are never blocked (ADR-0004).

2. Alerts and notifications on banner messages (use existing alerts/dispatcher; add alert types, do not build a second pipeline)
 - Alert types: banner direction change (e.g. BULLISH → MIXED, → BEARISH), stable-signal flip confirmed (hysteresis), Strong ↔ Weakening change, PCR band change (entering Oversold/Overbought gets severity "high"), max-pain move beyond a configurable number of strikes, OI-wall formed/broken at a watched level (psychological or user level), rollover/cost-of-carry bias flip, DTE milestones (expiry today / tomorrow), collector stale or failed (ops severity), market-closed suppression.
 - Rules: only on state change, never on every snapshot; per-type cooldown; dedupe key (tenant, underlying, alert_type, new_state, slot); optional digest at a configurable time with the day's banner timeline; quiet hours; severity → channel routing via existing severity_reaches floors.
 - Message template (English): "{underlying} OI banner: {old_direction} → {new_direction}. {message}. Put: {put_class}. Call: {call_class}. PCR {pcr} ({band}). Max pain {max_pain}. DTE {dte}. Data as of {timestamp}." Telegram: bold headline + optional per-strike OI chart image; buttons Open option chain / Open chart / Snooze 1h / Mute today (read-only actions; never an order — ADR-0006). Email: same body, HTML + text. Webhook: versioned JSON {underlying, alert_type, old_state, new_state, snapshot, data_timestamps}. Web push and in-app inbox: short form. SMS: shortest form, plan-gated.
 - Compliance wording (SCREENER_SPEC §6): messages state activity and bias; never "buy/sell/target/recommended". Copilot output filter applies.
 - Settings UI: per underlying enable/disable, which alert types, channels, cooldowns, digest time, quiet hours; test-send.

3. Tests (port Trade's tests/test_oi_analysis.py cases, in English, plus new ones)
 - Classification matrix, thresholds, insufficient data; signal generation all combinations; hysteresis: flip only after confirm_count + rotation, Weakening while unconfirmed, never false Strong; reconcile → MIXED on both contradiction types; PCR band edges inclusive/exclusive exactly as source; max pain against ATP's existing function; rollover proxy; gates fail-closed on stale/missing; snapshot idempotency per slot; aggregation takes last value per bucket; banner state machine change detection; alert dedupe/cooldown; template rendering; Telegram buttons never carry order actions; stale collector ⇒ ops alert and banner chip; strike step per underlying (fixture underlyings with different steps give consistent ATM windows).

4. Build order (one draft PR each)
 O1 oi_regime.py pure functions + settings model + tests (ported logic, English).
 O2 Snapshot collector + tables + migrations + stale detection + history API.
 O3 Banner API + frontend Banner, history table, per-strike OI chart; placements (dashboard, option-chain page, chart options layer).
 O4 Alert types + rules + templates on the existing dispatcher + settings UI + tests.
 O5 Strategy-engine gates wiring (opt-in conditions in Strategy Builder) + docs.
 Acceptance: same inputs → same outputs as the Trade functions (golden fixtures captured from the Trade test cases); banner updates every 5 minutes in session with timestamps; a direction change produces exactly one notification per channel; stale data shows a chip and suppresses alerts; no strings in Marathi in code or UI; no symbol-specific constants.
