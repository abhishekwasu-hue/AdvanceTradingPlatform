From Abhi — Screener addendum U8: every screener result opens a chart with the screen's conditions DRAWN on it, so the user can cross-verify how the screen worked (English). Applies to all screens (pre-built, Legends, breakout, price-action, indicator, F&O, user-built) and all result surfaces (result table, chart grid, alerts, Telegram, journal). Same working rules; draft PRs; tests; English strings.

0. Owner rule — minimal chart: the evidence chart shows ONLY the screen's own conditions. No other layers, indicators, zones, drawings or markers are rendered on an evidence chart, even if the user has them on their normal chart; the user's personal layers are available behind an explicit "Show my layers" toggle, off by default. Within the screen, each block draws exactly one compact drawable (one band, one box, one highlighted bar, one line), labelled by its block summary; failed conditions are hidden unless debug is on. Rendering budget per evidence chart: at most one drawable per block and one multi-timeframe strip; if a screen has many blocks, the panel lets the user toggle blocks, and the image for Telegram draws only the blocks that define the signal (level, trigger candle, volume, trend) with the rest in the caption. Snapshot tests fail if an evidence chart contains anything not in the evidence pack.

1. Principle: a screen never returns just a symbol. It returns the symbol plus an "evidence pack": for every block/condition that matched (and, in debug mode, those that did not), the exact values, the bars and the geometry needed to draw that condition. The chart layer renders this pack. Nothing is drawn from a separate re-computation — the chart shows what the engine used (same numbers, same bars, same timeframe, same as-of time).
2. Evidence pack (schema `evidence/1`, stored with the run and with each alert):
 - run_id, screen version, symbol, timeframe(s), as_of bar time, data tier and timestamps.
 - Per block: block id, plain-English summary (from U2), pass/fail, numeric values with units (e.g. RSI(14)=63.2; relative volume=2.1×; distance to level=0.4 ATR), and one or more drawables.
 - Drawable types: horizontal level/zone band (price range, from–to bars, label, state), line segment (trendline/channel, two anchors), box (consolidation/range/opening range/Darvas box/VCP contractions), bar highlight (breakout bar, commitment candle, pattern candles, NR7 bar, inside bar with mother bar), marker (pivot H/L, swing, HH/HL/LH/LL tag, BOS/CHoCH), indicator overlay/pane with the exact parameters (EMA 20/50/200, Bollinger, Donchian, VWAP, RSI, ADX…) and the threshold line that was tested (e.g. RSI 60 line), OI/IV panes for F&O conditions (OI walls as bands on the price chart), gap shading, measured-move/target and stop lines when the screen defines them, multi-timeframe context panels (small W/D/1H strip showing the trend tag used).
 - Geometry is in bar-index + price terms (engine-neutral), rendered by the ChartEngine abstraction (CHARTING_SPEC CH1/CH3) in both the embedded ProChart and the full chart workspace.
3. UI
 - Result row → "Show on chart" opens the symbol chart at the signal timeframe, scrolled to the as-of bar, with the evidence layer ON and a right-side "Why it matched" panel listing blocks; hovering/tapping a block highlights its drawables; toggling a block hides its drawing; "Show failed conditions" (debug) draws what did not pass in grey.
 - Chart grid view renders mini charts with the evidence layer for the first N results; Telegram/alert images are rendered with the same layer (the caption lists the block summaries); the journal keeps the evidence image and pack with the trade.
 - A "verify" strip under the chart shows each block's value next to its threshold (e.g. "Close 1,842 > range high 1,830 (+0.6 ATR) ✅", "Volume 2.1× avg ✅", "Daily trend UP ✅"); numbers are the engine's, with the data timestamp.
 - Replay: step back bar by bar; the evidence layer recomputes as-of each bar (CHARTING_SPEC CH3), so the user can see the moment the condition became true.
4. Engine requirements: every ScreenQL function/registry entry that can appear in a condition declares how it is drawn (a `drawable()` method returning geometry from its own inputs) — no block may be added without it (U3 definition of done); evidence packs are produced in the same pass as the match (no second computation); size-bounded (cap drawables per block; summarise beyond the cap); stored for the retention window of runs/alerts.
5. Tests: snapshot tests that each pre-built screen's evidence renders the expected drawables on fixtures; value parity test (numbers in the verify strip == numbers used by the evaluator); no-look-ahead test (evidence for as-of T contains no bar after T); Telegram image contains the layer (pixel-diff on fixtures); replay consistency; accessibility (labels readable in dark/light, colour-blind variant).
6. Order: EV1 evidence schema + drawable() on indicator, level, range, candle, volume blocks + "Show on chart" + verify strip → EV2 price-action/breakout/pattern drawables + chart grid + Telegram images → EV3 F&O (OI/IV) drawables + multi-timeframe context strip + replay → EV4 Legends/user-built screens coverage check (lint: every registry entry has drawable()). Slot right after U6 BK1 so breakout screens ship with evidence from day one.
