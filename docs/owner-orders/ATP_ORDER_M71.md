M71 · ATP · PERMANENT fix for broker API limits (supersedes M70 SC-1/SC-4; M70 SC-2/SC-3/SC-5 stay)
Research R33: Upstox standard APIs incl. historical candles = 50/s, 500/min, 2,000 per 30 min (exceeding may suspend access); orders separate (10/s, 500/min, 2,000/30 min for regular algos). Kite: historical 3/s, quote 1/s, orders 10/s + 200/min + 3,000/day. ATP today: rate_budget.py Upstox 8/s/200 per min and NO 30-minute window; the screener, charts, Copilot and engine each fetch REST history per symbol per request. Fetch-per-request can never scale to 50+ symbols × several timeframes × many users.
PL-1 Own market-data store is the single source for every feature (Screener, Charts, Terminal, Copilot, engine, backtests): (a) Daily/Weekly for every NSE symbol from the official NSE bhavcopy (already ingested) — zero broker calls; (b) intraday: the worker keeps a broker WebSocket market-data feed subscribed to the active universe (indices, F&O stocks, every user watchlist symbol) and builds 1-minute bars server-side, resampled to 5m/15m/1H with the session/auction rules (DP flags); (c) one-time paced backfill of intraday history per symbol (respecting every limit window), afterwards only gaps are fetched by REST. Store per (symbol, interval) with last-bar bookkeeping; features read locally.
PL-2 Budgets = each broker's PUBLISHED limits from its docs, all windows (per second, per minute, per 30 min, per day), separate pools for data vs orders, held per credential in Redis (shared by every process), with a safety margin as a setting (default 10 %). On HTTP 429 / "too many requests": exponential back-off + jitter, never a user-facing failure; orders and exits draw from their own pool and are never starved by data calls (exits get a reserved share).
PL-3 Order of reads: store → missing newest bars by REST (paced) → never the full history per run. A second run on the same symbols makes zero history calls (test).
PL-4 Feed health: subscription limits per connection from the broker's docs; auto-reconnect; gap detection after reconnect fills only the gap; status on the admin page (symbols subscribed, last tick age, gaps filled today).
PL-5 Business scale decision for the owner (log it, default = (1) now): (1) per-user own-broker data for that user's own use + the owner's data credential feeding the shared store for indices/universe; (2) a licensed market-data vendor for all users. Read docs/BROKER_DATA_TERMS.md and state which option each broker's terms allow for a SaaS; do not redistribute broker data against its terms.
PL-6 Tests + proof: limiter honours all windows (fake clock), 429 back-off, exits reserve; a NIFTY 50 1H scan and a 50-symbol chart grid with zero "could not be read"; calls per day before/after; the feed status screenshot.
