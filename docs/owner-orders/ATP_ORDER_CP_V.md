# Owner order CP-V (24 Oct 2026, verbatim)

OWNER ORDER — AI Copilot chart reading (roadmap ID CP-V). ≤25-line report. CV1 Data first: for "read the chart", fetch candles for Weekly, Daily, 1H, 15M from the user's connected broker (fallback: the lake after DATA-H backfill). Never answer from an empty lake. CV2 Render clean chart images (one per TF, candles + volume, no indicators unless asked, last closed bar only, no future data) and send them with the OHLC tables to Claude vision, using a fixed question set: trend per TF (higher highs/lows or lower highs/lows or range), nearest zones above/below with prices, where price is relative to them, false breaks / breaks seen, what to watch next. CV3 Numbers come from the data, never from the image: every price the answer states must exist in the OHLC table or the engine's levels; the model is told to quote only those. The answer shows a small "read by vision + data" label and the chart images it used. CV4 Information only: no buy/sell instruction; AI never places, blocks or changes orders. CV5 Cost control: per-user daily limit and per-call cost in settings; show remaining reads; admin sees total spend. Cache a read per symbol per closed bar. CV6 When data is missing or short, say exactly what is missing (no "structure: none"). CV7 Proof: 3 screenshots (NIFTY, BANKNIFTY, a stock) with the images used, cost per read, and a check that every quoted price exists in the data. Note: the full price-action reader comes to ATP only after it is approved in Trade (P5-1); CP-V is the interim reading and stays as a second opinion after that. CP-V output (extends CV1–CV7). ≤25-line report. CV8 Fixed checklist sent with every read (same order, versioned in settings): trend per TF; external swings; zones above/below (price range, TF, fresh/tested); breaks and false breaks seen; current location of price; confluence (zone + line / multi-TF); room to the next opposite zone; data gaps. CV9 Vision returns SHORT structured JSON per checklist item (no free drawing, no coordinates). Every price is validated against the OHLC/engine data; an item that fails validation is dropped and listed as "not confirmed". CV10 Annotated chart drawn by our code from the validated JSON: zones as bands (colour by role), external swings marked, false breaks / breaks labelled, trend arrow per TF, current price line. Shown on screen (phone + desktop) and downloadable as PNG (and the table as CSV). CV11 Tabular explanation: one row per checklist item — item · reading · evidence (prices/times from data) · confidence (high/medium/low from the model, shown as text). CV12 Area of interest: highlight the single highest-quality zone near price, with its factors in the table (trend alignment, freshness, departure strength, confluence, room to next zone). Wording is informational ("area of interest"), never a buy/sell call, no entry/stop/target numbers; disclaimer line once. (Regulatory note: naming levels as buy/sell calls needs a SEBI RA licence; owner will get legal review before public launch.) CV13 Proof: 3 annotated reads (NIFTY, BANKNIFTY, a stock) with PNG download working, the validation log (items dropped), cost per read.
