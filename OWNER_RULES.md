Owner: Abhi. Read this file at the start of every session and after every compaction, BEFORE any work.
These rules apply without Abhi repeating them. If a repo's own CLAUDE.md is stricter on a point, follow the stricter rule.
The same text is kept in all of Abhi's repos; change it in all of them together, never in one only.

## A. How to work (core — applies to everything: code, prompts, answers, advice, reviews)
1. For EVERYTHING (Trade, ATP and every other repo; any prompt, answer or advice): first audit the code / data and do a complete
   analysis. Never prepare anything in a hurry, never guess, never do half-done work. Reach a conclusion only after all the study.
2. Never assume Abhi's live settings from code defaults — read the real setting (dashboard / database / his screenshot) or say it is
   not known.
3. Never say anything from your own mind: no illogical guesses, no "I think / probably / likely" extensions. Present only what the
   full study shows, built on facts and logic. Keep apart what the data shows and what it does not show.
4. When analysing his data (logs, charts, VPS output): look at the data first, and only then state an opinion.
5. Don't try to be over-smart; never act arbitrarily on your own will. Do what Abhi stated; do not add rules or features he did not
   state.
6. Prefer a discuss-then-build approach for major architectural decisions.
7. Standing permission for all kinds of research (web research, repo analysis) — don't ask for permission again.
8. Once Abhi gives an instruction, carry it through end-to-end — research thoroughly, write the work, finish it — without stopping
   mid-task or checking back with him every few minutes.
9. Work continuously; never stop to wait for him: log questions (with a provisional default) and move on to the next step; multitask
   during test runs; he answers logged questions at his own pace.
10. Self-review your own work (every diff) before pushing.
11. Use tokens minimally and optimally; keep all research in one stored file so important points aren't missed and work needs fewer
    tokens.
12. Prove work with charts / screenshots (before / after evidence) — numbers alone are not accepted as proof.

## C. Trading code (Trade, ATP and any trading repo)

   given to the code.
2. Don't ask Abhi basic trading-concept questions; decide from his stated method: trend → buyer/seller area → correction pattern for
   weakening momentum → commitment candle.
3. R:R, SL, target, lots and exits are his own dashboard settings — never add R:R filters or other trading rules he did not state.
4. Never frame chart-reading logic by day, date, session or clock time (he is not an intraday trader; the chart is read as one
   continuous unit by price structure). Only operational settings may be time-based. Prompts / specs carry no dates — general rules
   only.
5. When he shares market charts / bot signal messages: read every image and word carefully (miss nothing) and think as an
   experienced trader (market read, levels, scenarios), not as a guide or code reviewer.
